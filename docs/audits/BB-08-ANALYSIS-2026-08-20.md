## Critical Issues Found

### Issue #1: Missing `webrtcAdditionalHosts` Configuration
**Evidence**: Production config shows NO `webrtcAdditionalHosts` set, only `stun:stun.l.google.com:19302` for STUN servers.

**Impact**: Users behind NAT/firewalls cannot connect WebRTC connections successfully because browsers need explicit host address announcements.

**Location**: `/opt/sigap/mediamtx.yml` in production lacks `webrtcAdditionalHosts` parameter.

## Recommended Actions

### Immediate Fix (Priority: HIGH)
Add `webrtcAdditionalHosts` to MediateMX configuration with publicly accessible IP/host. This allows WebRTC connections from external networks to connect successfully.

**Configuration needed**:
```yaml
webrtcAddresses: [":8889"]
webrtcLocalUDPAddress: ":8189"
webrtcICEServers2:
  - url: stun:stun.l.google.com:19302
webrtcAdditionalHosts:
  - <public-ip-or-hostname>:8889
```
